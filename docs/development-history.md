# 开发历史记录

以下是发布前的开发记录；其中版本标题不代表已公开发布的版本。

## 0.1.1 界面与 Windows 修复

- Windows Git 子进程统一使用无控制台标志，刷新、Fetch、暂存和提交不会创建 Git 终端窗口。
- 默认窗口为 1080×700 逻辑像素，启动时根据屏幕工作区与显示缩放缩小；最小窗口为 720×480，小窗口使用可滚动的单列布局。
- 新增「偏好设置」页面：默认亮色，可切换暗色或跟随系统，支持蓝色、紫色、绿色与石墨主题色，并配置最近提交条数。修改立即生效并在本机保存。
- 用 shadcn-vue 的导航按钮、卡片、标签页、提示、选择框和复选框重新组织仓库界面。
- Windows 路径显示与复制去除驱动器路径的 `\\?\` 前缀；网络路径转换为正常 UNC 格式。原路径保留用于 Git 和文件访问。

```sh
node --test tests/preferences.test.mjs
cargo test --manifest-path src-tauri/Cargo.toml --lib
pnpm tauri build --bundles nsis
```

`pnpm dev` 后可打开 `/tests/preview.html` 检查示例仓库界面。此入口使用模拟 IPC 和剪贴板，不读取或修改真实仓库，也不会包含在生产安装包中。

## 0.1.2 分支入口与文件状态

- 移除顶部三个全局统计卡片，仓库列表仍显示总数，每个仓库保留自己的分支数与同步差异。
- 「切换分支」固定显示在仓库顶部，通过弹窗选择本地或远端分支。
- 选择远端分支时，明确确认新建本地分支的名称、远端跟踪关系与切换操作；已有同名本地分支不会被覆盖。
- 工作区有改动、冲突或未完成的 Git 操作时，弹窗说明原因；可进入审阅提交，处理并刷新后再切换。
- 文件列表和提交弹窗将 Git 状态码显示为「未跟踪」「已修改」「新增」「已删除」等中文状态，悬停显示暂存区与工作区状态。

## 开发预览：仓库总览重构

- 总览改为独立的仓库集合页面，支持网格、列表布局，布局选择保存在本机。
- 每个仓库右上角提供功能菜单：查看详情、切换分支、Fetch、审阅提交、快进拉取、推送和复制路径。拉取与推送根据仓库状态启用。
- 点击仓库卡片进入 `/repositories/:id` 详情页面；通过返回按钮或主导航返回总览。
- 搜索、勾选和批量同步保留；全选只作用于当前搜索结果，并保留其他已选仓库。
- 总览只读取仓库摘要；进入详情后加载文件树、改动与提交记录，菜单中的提交操作按需读取工作区改动。

## 开发预览：详情分支管理

- 详情按「总览 → 分支 → 工作区」排列；分支模块区分本地与远端，支持搜索。
- 新建本地分支可选择 HEAD、本地或远端分支作为起点，并选择是否创建后切换。远端起点建立跟踪关系。
- 切换复用确认弹窗；远端分支可创建本地跟踪分支并切换。
- 合并明确显示「来源分支 → 当前分支」，确认时后端再次核对目标分支。未提交改动、冲突和进行中的 Git 操作阻止合并。
- 删除只针对本地非当前分支，需确认，且提交必须已合并到当前 HEAD；不提供强制删除或远端删除。
- 操作结束（包括合并失败）刷新仓库状态，以显示冲突或待继续的操作。

## 仓库添加与克隆

- 「添加仓库」下拉菜单提供「从本地添加」与「从远程添加」，侧栏和空状态入口保持一致。
- 远程添加支持 HTTPS / SSH 地址、选择已有存放目录及自动建议项目目录名；克隆成功后自动登记仓库。顶部加号提供「快速克隆仓库」，默认仅下载代码，可用开关选择登记。
- 最近 8 个存放目录保存在 SQLite，自动去重；支持点击选择、删除单条历史和清空历史。
- 弹窗展示 Git 输出和按接收、解析、检出阶段估算的总体百分比，成功后显示 100%。关闭弹窗后任务继续，可从任务中心重新打开。任务记录持久化，异常退出后标记为中断。
- 点击「停止」选择保留或删除文件。停止会终止 Git 进程树，完成后才按选择清理本次创建的项目目录；保留的不完整代码不会登记为仓库。
- 私有仓库使用本机 Git 凭据或 SSH 密钥；固定扫描目录仍在设置的「仓库」分类管理。
- 仓库详情固定显示名称、远程地址及刷新入口，下方按总览、分支管理、提交历史、工作区分为四个标签，内容内部滚动。
- 外观支持跟随系统、主题色、侧栏宽度、圆角和字号，侧栏底部支持折叠和亮暗快捷切换。
- 开发版数据位于 `%LOCALAPPDATA%/RepoDeck-dev`；安装版数据位于安装根目录的 `setting` 和 `data`。读取旧目录配置时保留旧文件，复制有效配置到新位置。旧品牌键名只保留作数据兼容使用。
- 窗口正常尺寸、位置与最大化状态保存到 `setting/window.json`，恢复时将窗口限制到当前显示器工作区。
- 当前远程：`https://github.com/yeyongzhi/RepoDeck.git`，开发分支：`dev`。

启动桌面开发预览：`pnpm tauri:dev`。

## 本地数据与 P1 / P2 产品完善

- 业务数据统一保存在安装目录 `data/repodeck.sqlite`：仓库登记、扫描目录、分组、置顶、历史目录、最近访问、上次打开项目及任务记录。开发版继续使用 `%LOCALAPPDATA%/RepoDeck-dev`，不向源码目录写数据。
- 界面偏好、默认编辑器／终端保存在 `setting/preferences.json`，窗口状态保存在 `setting/window.json`。仓库代码和 Git 元数据保留在原位置。
- 启动时按分类迁移旧 JSON 和 WebView 数据；优先采用原本的本机业务文件。旧文件保留，数据库已有数据不会被旧缓存覆盖。
- 设置 → 数据：导出／合并导入业务 JSON 数据包，以及独立导出／导入偏好 JSON。业务数据包是数据库的可迁移快照，不包含项目代码和 Git 凭据。导入前预览失效路径，并自动在 `backup` 保存原数据快照；失败事务回滚。
- 总览支持组合状态筛选、按置顶顺序优先排序、批量加入分组，卡片优先展示当前分支、改动数量和同步差异，并显示最近获取远端时间。
- 克隆支持选择完成后加入的分组、失败原因说明、详细日志、打开目录和重试到新目录。快速克隆默认只下载代码，按钮明确区分「克隆」与「克隆并添加」。
- 任务中心统一查看克隆与 Git 操作记录。关闭应用时可返回、等待完成后退出，或停止克隆并保留文件后退出；Git 写入任务执行期间不强行退出。
- 失效仓库可重新定位，保留分组、置顶和最近访问关系；只更改登记，不移动文件。通用设置可配置默认编辑器和终端，仓库快捷菜单支持文件管理器与规范化路径复制。
- 详情常用标签保留，分支对比、Stash、标签及记录收进「更多工具」，窄窗口换行布局。
