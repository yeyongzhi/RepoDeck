## 1. 项目简介

**RepoDeck** 是一个面向 Windows 和 macOS 的桌面 Git 仓库管理工具。用户可以添加一个单独的项目仓库，也可以添加代码集合目录（例如 `E:/Code`），由应用发现其中的 Git 仓库，并集中查看目录、远端、分支、提交和同步状态，再对一个或多个仓库执行常见 Git 操作。

## 当前实现

**已实现**：Tauri 2 + Vue 3/TypeScript + Tailwind CSS + shadcn-vue 桌面骨架；扫描目录添加、移除与本机持久化（重复添加有提示）；按 `.git` 元数据发现和去重仓库；显示当前分支、远端、本地/远程分支、工作区改动和缓存的 ahead/behind；按需展开目录树；查看所选分支最近提交（默认 10 条，可设 1–100，暂存于本机 WebView localStorage）；Fetch、受保护的快进拉取、当前分支推送、本地分支切换、设置 upstream；勾选文件、暂存和路径限定提交；分叉时由用户选择合并或变基，发现冲突后要求外部处理且阻止暂存/提交/推送；批量 Fetch 并只自动快进干净且纯落后的仓库。

**0.1.1 已补充**：修复 Windows Git 子进程弹出终端窗口的问题；减小默认窗口并按屏幕工作区与显示缩放自动适配；新增亮色/暗色/跟随系统和主题色设置；最近提交条数并入偏好设置；使用 shadcn-vue 标签页、选择框和复选框优化布局；Windows 路径显示及复制去除内部前缀。

**仍在开发/后续完善**：macOS 原生构建验证；目录深度和排除项设置；外部 IDE/终端快捷打开；更细的批量逐仓库操作恢复与取消体验。未实现能力仍按后文 P0/P1 需求跟踪。

## 2. 问题与目标

当开发者把多个项目分散在不同位置，或集中放在一个父目录中时，逐个打开终端检查分支、远端和更新状态会产生重复操作。RepoDeck 旨在提供一个可搜索、可批量处理的本地工作台。

### 目标

- 允许登记单个仓库路径或包含多个仓库的集合路径。
- 自动发现并集中展示目标仓库及其 Git 状态。
- 快速执行分支切换、获取远端更新、拉取和推送。
- 支持跨仓库批量同步，并明确显示每个仓库的成功、跳过或失败原因。
- 在 Windows 和 macOS 上提供一致的基本体验。

### 成功标准（建议）

- 用户能清楚区分单个仓库和集合目录，扫描结果可追溯到原始路径。
- 对常见 Git 状态和批量操作结果，用户不必逐个打开仓库才能判断。
- 批量操作不会静默覆盖未提交改动；失败和跳过项均有可读原因。
- 重启应用后仍能恢复已添加的扫描路径和用户设置。

## 3. 用户与主要流程

### 目标用户

首期面向个人开发者。多人团队协作、账号和云端共享暂不纳入首期。

### 主要流程

1. 用户添加一个仓库目录或集合目录。
2. 应用扫描目录，识别 Git 仓库并显示仓库列表。
3. 用户查看仓库的当前分支、工作区状态、远端和本地/远程分支。
4. 用户展开仓库查看目录树、分支提交摘要和同步差异。
5. 用户选择单仓库操作，或在批量操作前检查目标范围与结果。
6. 操作完成后，应用逐仓库呈现成功、跳过、失败及原因，并刷新状态。

## 4. 首期范围

### P0：首期必需

| 编号 | 功能 | 用户可见行为与验收要点 |
|---|---|---|
| FR-001 | 添加和管理扫描路径 | 用户可添加、移除、重新扫描单仓库路径或集合目录；重复路径有提示；重启后路径仍保留。移除扫描路径不删除磁盘文件或仓库。 |
| FR-002 | 发现 Git 仓库 | 应用扫描已添加路径的下级目录并识别仓库；结果显示仓库路径。无效路径、不可访问路径和未发现仓库时给出说明。默认以 Git 元数据为确认依据；`src` 等目录可作为候选提示，不单独代表 Git 仓库。 |
| FR-003 | 仓库总览与刷新 | 列表显示仓库名称/路径、当前分支、远端、工作区是否干净，以及可获得时的 ahead/behind 信息。刷新单个仓库或全部仓库。 |
| FR-004 | 目录树 | 用户可浏览目标仓库的文件/目录树；支持展开、折叠和基本文件名检索。大目录采用按需加载。忽略目录与符号链接策略需在技术实现阶段固化。 |
| FR-005 | 远端与分支信息 | 展示仓库配置的远端、当前分支、本地分支列表、远端跟踪分支列表及数量。无远端、无分支或 detached HEAD 状态需明确显示。 |
| FR-006 | 分支提交摘要 | 展示各分支最近 N 条提交的摘要信息（提交标识、标题、作者和时间等）；N 可配置。全量历史暂不作为默认扫描内容。 |
| FR-007 | 单仓库 Git 操作 | 支持切换到已有本地分支、fetch、拉取当前分支跟踪的远端更新、推送当前分支，以及用户确认后的 merge/rebase。执行前检查工作区和分支关系；有未提交改动时先提示。 |
| FR-008 | 批量同步 | 用户可选择全部或部分仓库，批量检查并同步当前分支；只有工作区干净且本地严格落后于远端、可快进时才直接拉取。其他状态逐仓库提示并提供建议操作按钮。每个仓库独立产生结果，不因一个失败而中止其他仓库。详情见第 5 节。 |
| FR-009 | 操作结果与错误说明 | 显示每个仓库的本地/远端提交差异、建议操作、按钮、进度和结果；批量结果可按成功、待处理、跳过、失败筛选。支持复制错误详情。 |
| FR-010 | 本机设置 | 保存扫描路径、展示偏好和扫描排除项等轻量设置。首期不要求账户或远端服务。 |
| FR-011 | 提交前审阅与提交 | 首期提供变更文件选择、暂存和提交说明输入；只有用户确认后才创建提交。提交成功后才继续拉取。提交本身完成但后续拉取失败时，明确呈现已提交、未拉取的部分完成状态。 |
| FR-012 | 分支关系提示与操作 | Fetch 后区分已同步、本地落后、本地领先、分叉和缺少 upstream。展示领先/落后提交数；只有干净工作区且本地落后时直接快进。其他状态显示原因、建议和对应按钮；merge/rebase 需用户主动选择并确认，冲突交由外部工具处理。 |

### P1：有价值的后续增强

- 按名称、路径、分支、状态筛选和排序。
- 查看分支差异摘要、提交图或提交详情。
- 一键打开仓库所在文件夹、终端或用户配置的 IDE。
- 为仓库添加标签、收藏和分组。
- 自定义扫描深度和忽略目录。
- 操作历史导出与可复制的诊断信息。

### 暂不纳入首期

- 账号、团队权限、云端同步或集中托管 Git 服务。
- 文件编辑器、代码审查、合并请求管理和冲突解决 UI。
- 自动 stash、自动 rebase、自动强制推送或自动删除分支。
- 未经用户选择便对仓库执行后台拉取或推送。

## 5. 重要业务规则

### 仓库发现

- 单仓库路径若本身是 Git 工作树，应直接作为一个目标。
- 集合目录中以发现 `.git` 元数据的目录作为确认仓库；`.git` 既可能是目录也可能是 worktree 文件。
- `src`、`package.json` 等可作为“可能是项目”的提示或后续可选识别规则，不能仅凭它们执行 Git 操作。
- 同一仓库被多个扫描根目录发现时，列表只显示一个仓库，并保留关联扫描根。
- 是否允许嵌套仓库、扫描最大深度、符号链接处理和默认排除项为待确认/待技术验证事项。

### 批量同步与提交确认

对每个选中的仓库分别执行：

1. 检查路径、Git 仓库和当前分支；Fetch 后计算本地/远端领先与落后提交数。
2. 工作区和暂存区干净，且本地当前提交是远端跟踪分支的祖先、远端还有新提交（本地 `ahead = 0`、`behind > 0`）时，可快进拉取。
3. 两端指向同一提交时显示“已同步”，不重复拉取。
4. 其他状态先提示并展示差异及相应按钮：工作区有改动时可审阅文件、选择并暂存、填写说明后提交再继续，或跳过；本地领先时建议推送；本地与远端已分叉时可选择 merge、rebase、打开外部 Git 工具或跳过；缺少 upstream 时可选择远端跟踪分支或跳过。
5. 提交、push、merge 或 rebase 都必须由用户明确点击相应操作并确认。用户确认提交后，未选择的文件不能被隐式纳入；提交成功但后续同步失败时，必须分别报告已完成和未完成的步骤。
6. Merge/rebase 后若发生冲突，停止自动后续步骤并提示用户在 IDE/终端解决；不自动丢弃改动、不强制更新、不强制推送。一个仓库失败或跳过不影响其他仓库。

“一键拉取最新的远端同名分支代码到本地”暂按每个仓库的**当前分支**及其跟踪分支处理；更新所有本地分支会改变范围，暂不作为首期默认行为。

## 6. 关键界面与操作说明（拟议）

### 仓库工作台

- 侧栏：扫描根目录、添加入口、扫描状态。
- 主列表：仓库路径、当前分支、工作区状态、跟踪分支及同步差异、远端。
- 详情区：目录树、分支列表、各分支最近提交、操作结果。
- 顶部操作：刷新、批量同步、搜索/过滤。

### 添加路径

1. 选择“添加仓库”或“添加集合目录”。
2. 使用系统目录选择器选择路径。
3. 扫描并展示发现数量和无法访问/未识别路径的提示。
4. 确认后保存扫描根并显示发现的仓库。

### 单仓库同步

1. 在仓库列表选择“拉取/同步”。
2. 应用检查当前分支、工作区、upstream 和远端连通性。
3. 展示本地/远端领先与落后数量，并按状态提供建议按钮。
4. 工作区有改动时，用户可审阅文件、选择并暂存、填写说明，确认提交后再重新计算分支关系。
5. 只有本地落后且可快进时直接拉取；分叉时用户可选择 merge/rebase 或打开外部工具。冲突时停止并给出外部处理提示。

### 批量同步

1. 用户选择全部或部分仓库，并查看将参与操作的数量。
2. 应用逐个检查并执行可安全完成的同步。
3. 展示每个仓库的成功、跳过或失败状态，可打开详情并重试单项。

## 7. 非功能要求

- **平台**：Windows 与 macOS；具体最低系统版本及 macOS Intel/Apple Silicon 支持范围待确认。
- **安全**：本机优先；路径和命令参数按独立参数传递，不拼接 shell 命令；不主动读取或上传源文件内容。
- **可恢复**：Git 错误、超时、权限错误和网络错误均需可见，批量任务应保留逐项结果。
- **响应性**：扫描与 Git 命令不能阻塞界面；大型仓库分批或按需呈现目录和提交信息。
- **语言**：首期界面语言待确认；建议先中文，架构保留国际化能力。
- **可访问性**：关键操作可通过键盘使用，状态不能只依赖颜色表达。

## 8. 建议的验收场景

- 添加单仓库和包含多个仓库的父目录后，可正确发现、去重并展示仓库。
- 仓库含 `.git` 目录与 worktree `.git` 文件时都能识别。
- 无远端、detached HEAD、网络断开及不可访问目录均有明确状态。
- 只有干净工作区且本地落后远端的仓库会直接快进；相同提交显示已同步。
- 本地领先、分叉、工作区有改动或缺少 upstream 时，批量同步逐仓库提示并提供对应操作按钮。
- 用户选择提交后，可选择文件、暂存并填写说明；未选文件不会被隐式提交。
- 分叉仓库选择 merge/rebase 后如遇冲突会停止，并指引用户在 IDE/终端处理。
- 提交成功但 pull 失败时，结果能区分已提交和未拉取，不会声称整个同步成功。
- 工作区干净、远端领先且本地没有独有提交时完成快进；发生分叉或冲突时停止，不丢失本地改动。
- 不同仓库的批量操作结果逐项展示，用户可定位失败仓库。
- 重启后扫描根目录和设置仍存在。
